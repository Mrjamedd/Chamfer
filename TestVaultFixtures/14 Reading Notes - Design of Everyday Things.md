# The Design of Everyday Things — reading notes

The useful distinction so far is between a thing being complicated and it being confusing. A complicated tool can still explain itself if the possible actions are visible and the feedback is immediate.

## ideas to keep

- A signifier shows where an action can happen.
- Constraints can prevent an error before a warning has to explain it.
- Feedback needs to arrive close enough to the action that the two feel related.
- People blame themselves for bad interfaces far too quickly.

This connects to settings screens: if changing a value has no visible consequence, the user cant tell whether it worked. A success toast might help but showing the resulting state is better.
